実装課題2：セキュアな認証・認可機能を備えたNext.jsアプリケーション
1. プロジェクト概要
本プロジェクトは、Next.jsを用いて構築された、セキュリティを重視した認証・認可システムです。教材（web-sec-playground-2）をベースに、不要な機能を削ぎ落とし、セッションベース認証を軸とした堅牢な設計を実装しました。
2. 実装済み機能
2.1 基本機能
サインアップ機能: 新規ユーザー登録。
ログイン・ログアウト機能: セッションベースの認証管理。
プロフィール管理: ユーザー情報の表示および編集。
2.2 独自実装した追加機能（2つ以上）
パスワード強度表示機能
サインアップ時に、入力されたパスワードの強度（長さ、文字種）をリアルタイムで判定し、バーで視覚的にフィードバックします。
アカウント削除（退会）機能
ログイン済みユーザーが自らアカウントを削除できる機能を実装しました。削除時には関連するデータベースのレコードを物理削除し、セッションCookieも即座に破棄します。
3. セキュリティ対策
本アプリでは、以下のセキュリティ要件を厳格に実装しています
。
3.1 適切なパスワード管理 (bcrypt)
ユーザーのパスワードは平文で保存せず、bcryptjsライブラリを使用してハッシュ化してからデータベースに保存しています
。
ログイン時も bcrypt.compare を用い、安全に照合を行っています。
3.2 セキュアなCookie属性の設定
セッションIDを管理するCookieには、以下の属性を設定し、セッションハイジャックやCSRF攻撃のリスクを低減させています
。
HttpOnly: JavaScriptからのCookie参照を禁止し、XSSによるセッションID窃取を防止します。
Secure: HTTPS通信時のみCookieを送信するように設定しています。
SameSite=Lax: クロスサイトリクエストによるCSRF攻撃を防ぎつつ、利便性を確保しています。
3.3 Content Security Policy (CSP) の導入
next.config.ts において、**CSP（Content Security Policy）**を設定しました
。
信頼できるソース以外のスクリプト実行を制限し、万が一サニタイズ漏れがあった場合のXSS攻撃に対する「最後の砦」として機能させています
。
4. コードのクリーンアップ
課題の要件に基づき、以下の「実装に無関係なコード」はすべて削除しました。
未使用の認証方式: トークンベース認証（JWT）に関連するファイルやロジック。
不要な機能: 「ニュース」および「ショップ（カート）」に関連するAPI、フロントエンドページ、型定義。 これにより、認証機能に特化したシンプルで可読性の高いコードベースを実現しています。

6. セットアップ手順
パッケージのインストール: npm install
環境変数の設定: .env ファイルに JWT_SECRET（16文字以上）を設定
。
データベース初期化: npx prisma db push
シードデータ投入: npx prisma db seed
開発サーバー起動: npm run dev
